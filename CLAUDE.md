# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev` — start the dev server (Turbopack) at http://localhost:3000
- `npm run build` — production build
- `npm run start` — serve the production build
- `npm run lint` — run ESLint (`eslint .`). Note: `next lint` was removed in Next.js 16, so this calls ESLint directly via `eslint.config.mjs`, which imports `eslint-config-next`'s flat config array directly (not through the legacy `FlatCompat` shim — that combination crashes under ESLint 9).

There is no test suite configured in this project.

## Architecture

Next.js 16 (App Router) + React 19 + TypeScript + Tailwind CSS v4. A personal portfolio for Jeremia Sunny — home page composed of sections, plus per-project case-study routes.

- **Data-driven content**: every section reads from typed arrays in `src/data/` (`site.ts`, `links.ts`, `skills.ts`, `capabilities.ts`, `experience.ts`, `projects.ts`, `blog.ts`), typed via `src/lib/types.ts`. Components never hardcode copy — to update bio/skills/capabilities/experience/projects, edit the data files, not the components. `capabilities.ts` is the PRD's five capability areas; each entry carries a `proof` line that must point at something verifiable (a shipped project, or a behaviour of this page), otherwise it belongs in `skills.ts`.
- **Routing**: `src/app/page.tsx` composes the section components in order (Hero → About → Capabilities → ProjectsGrid → Skills → Experience → Blog → ContactCTA) — who, then what I can do, then proof, then the toolbox. `NAV_ITEMS` in `Navbar.tsx` mirrors that order; keep the two in sync. `src/app/projects/[slug]/page.tsx` is a statically generated case-study page (`generateStaticParams`) for any `Project` in `src/data/projects.ts` that has a `caseStudy` field; projects without one only appear as cards, with no route.
- **Two project tiers**: `src/data/projects.ts` exports `projects` (deep case studies with a `caseStudy` field — currently AI Case Review Analyzer and My Bill App, rendered in `ProjectsGrid`'s "Featured work" grid) and `clientWork` (lighter cards — client/agency sites and other personal builds, no `caseStudy`, no `githubUrl` since most don't have a public repo, rendered in the "More work" grid below). `ProjectCard` handles both shapes: it only renders a "Case study" link when `caseStudy` is present and a "Code" link when `githubUrl` is present. Screenshots live in `public/projects/<slug>/`; research notes (with `[ADD]` markers for anything not derivable from a public site visit) live in `details/projects/<slug>/notes.md`.
- **Component layout**: `src/components/layout/` (Navbar, MobileMenu, Footer, ThemeToggle, ThemeProvider, SkipLink, SmoothScroll), `src/components/sections/` (one per home-page section), `src/components/project/` (ProjectCard, CaseStudyHeader/Body, ProjectMockup), `src/components/motion/` (the GSAP primitives — see below), `src/components/hero/` (the WebGL hero — see below), `src/components/ui/` (Button, Tag, Container, Section, SectionHeading, TerminalWindow, brand icons, the lucide icon-name→component map used by `Skills.tsx` and `Capabilities.tsx`). `Section` owns section spacing (`py-20 sm:py-28`) and the container; use it rather than re-typing a `<section>`.
- **Theming**: dark by default, toggleable via `next-themes` (`attribute="class"`). Tailwind v4's `dark:` variant defaults to `prefers-color-scheme`, so `globals.css` overrides it with `@custom-variant dark (&:where(.dark, .dark *));` for class-based toggling. Design tokens are defined on `:root` and `.dark` and re-exposed as Tailwind colors via `@theme inline`: surfaces (`--background`, `--surface`, `--border`), accents (`--accent`, `--accent-2`, `--accent-soft`, `--glow`), elevation (`--shadow-card`, `--shadow-lift`), radius, and motion (`--duration-*`, `--ease-*`). The GSAP-side equivalents of the motion tokens live in `src/lib/motion.ts` — change both together so a CSS transition and a tween on the same element still read as one motion language. `html` carries `overflow-x: clip` (not `hidden`, which would break the sticky navbar) as a safety net for decorative layers.
- **Client/server split**: sections are server components by default; only genuinely interactive pieces are client components (`ThemeToggle`, `Navbar`/`MobileMenu`, `TypingRoles`, `ContactForm`, and everything under `motion/` and `hero/`). Sections stay on the server by composing the client motion primitives rather than becoming client components themselves. Hooks that read browser-only state (`useMounted`, `usePrefersReducedMotion`) use `useSyncExternalStore` rather than `useState`+`useEffect`, because `eslint-plugin-react-hooks`'s `set-state-in-effect` rule (shipped with `eslint-config-next` on Next 16) flags synchronous `setState` in effect bodies.
- **Contact form**: `src/components/sections/ContactForm.tsx` posts to `src/app/api/contact/route.ts`, which sends via Resend if `RESEND_API_KEY` is set, or returns a `not_configured` response the form turns into a `mailto:` fallback UI. See `.env.example` for the env vars (`RESEND_API_KEY`, `CONTACT_TO_EMAIL`, `NEXT_PUBLIC_SITE_URL`).
- **No brand icons in `lucide-react`**: GitHub/LinkedIn glyphs are hand-rolled inline SVGs in `src/components/ui/icons.tsx` — lucide dropped brand/logo icons, so don't try importing `Github`/`Linkedin` from it.
- **Smooth scroll**: `src/components/layout/SmoothScroll.tsx` wraps the app in `<ReactLenis root>` (from `lenis/react`), set up in `layout.tsx` inside `ThemeProvider`. `anchors: { offset: -16 }` makes every in-page `#hash` link (nav, mobile menu, hero CTA, skip link) glide instead of jump — no manual click handlers needed, Lenis's built-in anchor handling does it. `respectReducedMotion` is on by default (Lenis's own default, not something this repo sets), so `prefers-reduced-motion` users get instant jumps automatically — verified via Playwright, don't re-litigate it. `root` mode renders no wrapper `div`, so it doesn't affect layout/sticky positioning. `MotionProvider` sits *inside* `<ReactLenis>` and pipes every Lenis tick into `ScrollTrigger.update()` — without that, ScrollTrigger reads stale scroll positions and every trigger fires late.
- **Motion system (GSAP)**: plugins are registered exactly once in `src/lib/gsap.ts`; import `gsap`/`ScrollTrigger`/`useGSAP` from there, never from `gsap` directly. The reusable primitives in `src/components/motion/` are `Reveal` (scroll-triggered entrance, with a `stagger`/`selector` group mode), `SplitReveal` (word-by-word masked headline), `Parallax`, `Magnetic`, `TiltCard`, `ScrollLine`, `ScrollProgress` and `CustomCursor`. Two rules hold across all of them: every animation is built inside `gsap.matchMedia("(prefers-reduced-motion: no-preference)")` so reduced-motion visitors never get one, and pointer-driven effects additionally gate on `(hover: hover) and (pointer: fine)`. Reveal targets ship with the `motion-hidden` class so server-rendered content can't flash before GSAP takes over; the three ways it comes back are the reduced-motion query in `globals.css`, the `<noscript>` override in `layout.tsx`, and the `.motion-off` kill-switch. When nesting primitives, don't let two of them write the same transform property on one element — `Magnetic` and `TiltCard` both use an outer/inner span pair precisely so an enclosing `Reveal` has something untouched to animate.
- **3D hero**: `HeroVisual` (client) decides what to render from `useRenderTier()`, which returns `high`/`low`/`off` based on reduced-motion, WebGL support, `hardwareConcurrency` and `deviceMemory`; it server-renders as `off` so the static `HeroFallback` is what ships in the HTML. `HeroScene` (three.js + `@react-three/fiber`) is loaded via `next/dynamic` with `ssr: false` — which Next 16 only allows inside a Client Component — to keep ~450kB off the critical path. Rotation state lives in `src/components/hero/orbit.ts` as a module-scoped mutable object, *not* a React ref passed as a prop: `useFrame` mutating a prop trips `react-hooks/immutability`, and state would re-render at 60fps. That module must stay free of any `three` import or it would defeat the dynamic import. The render loop parks (`frameloop="never"`) when the hero scrolls out of view, particle positions come from a seeded PRNG because `Math.random()` during render trips `react-hooks/purity`, and the camera distance is set from `R / sin(fov/2)` so the outer shell never clips the frame. Scene colours mirror `globals.css` in `src/lib/theme-colors.ts` — the one place the palette is written twice.
- Path alias `@/*` maps to `src/*`.
